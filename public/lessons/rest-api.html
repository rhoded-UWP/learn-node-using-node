Lesson 7

A REST API with a database

How one URL, four HTTP methods, and a database table let a page add, read, change, and delete data.

The idea

Until now, every demo on this site has only read things. This lesson stores what visitors write: feedback about a lesson. Each piece of feedback is a row in a Postgres table named feedback, so it is still there after the server restarts.

A REST API organizes this around one resource, feedback, at one URL, /api/feedback. A single piece of feedback has its own URL with its id on the end, such as /api/feedback/3. The HTTP method says what to do with it:

  • GET reads: the whole list, or one row by id.
  • POST adds a new row.
  • PUT replaces a row's lesson and message.
  • DELETE removes a row.

The browser sends data as a JSON body, and the server answers with JSON. The status code says how it went, so the page can tell success from failure without reading the body.

The server never trusts what it is sent. It checks every id, lesson, and message itself, and answers 400 when something is wrong. The form on this page does no checking of its own, so you can see those answers.

The code

This is the code behind the demo, copied from this site's own source. First, the table. setupDatabase() in db.js creates it once, before the server starts listening:

db.js 
// Lesson 7: visitors' feedback. CHECK makes the database itself refuse
// a lesson outside 1 to 7 or a message outside 1 to 500 characters.
await query(`
  CREATE TABLE IF NOT EXISTS feedback (
    id         SERIAL PRIMARY KEY,
    lesson     INTEGER NOT NULL CHECK (lesson BETWEEN 1 AND 7),
    message    TEXT NOT NULL CHECK (char_length(message) BETWEEN 1 AND 500),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
  )
`);

SERIAL makes Postgres number the rows 1, 2, 3, and so on, and never reuse a number. DEFAULT now() fills in the time when a row is added.

In server.js, express.json() reads a JSON request body into req.body. app.route joins several methods to one path. :id is a route parameter: whatever is in that part of the URL arrives as req.params.id. Any method a route does not list gets a 405.

server.js 
// Lesson 7: the feedback API. Each handler is in feedback.js.
// express.json() reads a JSON request body into req.body.
app.use('/api', express.json());

// Answers any method a route does not list, with the ones it does.
function onlyAllow(methods) {
  return (req, res) => {
    res.set('Allow', methods);
    res.status(405).json({ error: `Method not allowed. Use ${methods}.` });
  };
}

app.route('/api/feedback')
  .get(listFeedback)
  .post(createFeedback)
  .all(onlyAllow('GET, POST'));

app.route('/api/feedback/:id')
  .get(getFeedback)
  .put(updateFeedback)
  .delete(deleteFeedback)
  .all(onlyAllow('GET, PUT, DELETE'));

When the body is not valid JSON, express.json() throws before any handler runs, and Express sends the error to the error-handling middleware. This part of it turns that error into a 400:

server.js 
// express.json() could not read the body. That is the visitor's mistake: 400.
if (error.type === 'entity.parse.failed') {
  console.error('Bad JSON body:', error.message);
  return res.status(400).json({ error: 'The body is not valid JSON.' });
}

The five handlers, and the helpers that check their input, are in feedback.js. Every value goes into the SQL as $1, $2, or $3, never pasted into the SQL text. RETURNING asks Postgres to send back the row it just added or changed.

feedback.js 
// The biggest id a SERIAL column can hold. Postgres refuses bigger numbers.
const MAX_ID = 2147483647;

// Reads :id from the URL. Sends a 400 and returns null if it is not a whole number.
function readId(req, res) {
  const { id } = req.params;
  if (!/^\d+$/.test(id) || Number(id) > MAX_ID) {
    res.status(400).json({ error: `id must be a whole number up to ${MAX_ID}.` });
    return null;
  }
  return Number(id);
}

// Checks a POST or PUT body. Sends a 400 and returns null if anything is wrong.
function readBody(req, res) {
  const body = req.body;
  if (typeof body !== 'object' || body === null || Array.isArray(body)) {
    res.status(400).json({
      error: 'Send a JSON object like {"lesson": 7, "message": "..."} with Content-Type: application/json.',
    });
    return null;
  }
  const { lesson, message } = body;
  if (!Number.isInteger(lesson) || lesson < 1 || lesson > 7) {
    res.status(400).json({ error: 'lesson must be a whole number from 1 to 7.' });
    return null;
  }
  if (typeof message !== 'string' || message.trim() === '') {
    res.status(400).json({ error: 'message is missing or empty.' });
    return null;
  }
  if (message.trim().length > 500) {
    res.status(400).json({ error: 'message must be 500 characters or fewer.' });
    return null;
  }
  return { lesson, message: message.trim() };
}

// The answer when no row has that id.
function notFound(res, id) {
  res.status(404).json({ error: `No feedback with id ${id}.` });
}

// GET /api/feedback and GET /api/feedback?lesson=N: every row, newest first.
export async function listFeedback(req, res) {
  const { lesson } = req.query;
  if (lesson === undefined) {
    const result = await query(
      'SELECT id, lesson, message, created_at FROM feedback ORDER BY created_at DESC, id DESC',
    );
    return res.status(200).json(result.rows);
  }
  if (!/^[1-7]$/.test(lesson)) {
    return res.status(400).json({ error: 'lesson must be a whole number from 1 to 7.' });
  }
  const result = await query(
    'SELECT id, lesson, message, created_at FROM feedback WHERE lesson = $1 ORDER BY created_at DESC, id DESC',
    [Number(lesson)],
  );
  res.status(200).json(result.rows);
}

// GET /api/feedback/:id: one row.
export async function getFeedback(req, res) {
  const id = readId(req, res);
  if (id === null) return;
  const result = await query(
    'SELECT id, lesson, message, created_at FROM feedback WHERE id = $1',
    [id],
  );
  if (result.rows.length === 0) return notFound(res, id);
  res.status(200).json(result.rows[0]);
}

// POST /api/feedback: adds a row and answers with it, id and all.
export async function createFeedback(req, res) {
  const input = readBody(req, res);
  if (input === null) return;
  const result = await query(
    'INSERT INTO feedback (lesson, message) VALUES ($1, $2) RETURNING id, lesson, message, created_at',
    [input.lesson, input.message],
  );
  res.status(201).json(result.rows[0]);
}

// PUT /api/feedback/:id: replaces a row's lesson and message.
export async function updateFeedback(req, res) {
  const id = readId(req, res);
  if (id === null) return;
  const input = readBody(req, res);
  if (input === null) return;
  const result = await query(
    'UPDATE feedback SET lesson = $1, message = $2 WHERE id = $3 RETURNING id, lesson, message, created_at',
    [input.lesson, input.message, id],
  );
  if (result.rows.length === 0) return notFound(res, id);
  res.status(200).json(result.rows[0]);
}

// DELETE /api/feedback/:id: removes a row. 204 means "done, nothing to send".
export async function deleteFeedback(req, res) {
  const id = readId(req, res);
  if (id === null) return;
  const result = await query('DELETE FROM feedback WHERE id = $1', [id]);
  if (result.rowCount === 0) return notFound(res, id);
  res.status(204).end();
}

Each helper sends a 400 itself and returns null. The handler sees the null and stops with return, so it never sends a second answer.

    What just happened
    
      
    When the page opened, it sent GET /api/feedback and got
      HTTP 200 OK with a JSON array, newest first. The page
      drew the list from that array. Each button clears the Requests box and
      shows its own request there. When that request works, a fresh
      GET /api/feedback follows to redraw the list.
    
      
    When things went right
    
      
      
        
    • Send feedback: HTTP 201 Created. The page sent
        POST /api/feedback with a body like
        {"lesson": 7, "message": "..."}. The answer is the new
        row, with an id and created_at that the
        database filled in. Spaces at the start and end of the message are
        trimmed off.
      • 
        
    • Save changes: HTTP 200 OK. Edit sent
        PUT /api/feedback/ plus the row's id. The answer is the
        changed row. Its id and created_at did not
        change.
      • 
        
    • Delete: HTTP 204 No Content.
        DELETE worked, and 204 means there is nothing to send
        back, so the request shows (no body).
      • 
      
    
      
    When the server said no
    
      
      
        
    • Empty message: HTTP 400 Bad Request, with
        "message is missing or empty." A message of only spaces
        gets the same answer.
      • 
        
    • Lesson 9, 0, 2.5, or empty: HTTP 400 Bad Request,
        with "lesson must be a whole number from 1 to 7."
      • 
        
    • A message over 500 characters: HTTP 400 Bad
        Request, with "message must be 500 characters or
        fewer."
      • 
        
    • id 9999: HTTP 404 Not Found, with
        "No feedback with id 9999." 9999 is a fine id, but no row
        has it. Deleting a row that is already gone gets the same kind of
        answer.
      • 
        
    • id abc: HTTP 400 Bad Request, with
        "id must be a whole number up to 2147483647." The server
        never asked the database, because abc can never be an id.
        2147483647 is the biggest number a SERIAL column can
        hold.
      • 
      
    
      
    After a 400, the form keeps what you typed so you can fix it. Nothing
      was saved: the list did not change.
    
      
    The difference matters. 400 means "your request is
      wrong, fix it". 404 means "your request is fine, but
      that thing is not here". 201 and 204
      are more exact ways to say "it worked" than 200.
    
      
    If you type something like <b>hi</b> as a
      message, it shows in the list as those exact characters, not as bold
      text. The page puts every message on the screen with
      textContent, which never treats text as HTML.
