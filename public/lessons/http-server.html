Lesson 1

The HTTP server

How a Node.js server receives a request and answers it with a status code, a Content-Type, and a body.

The idea

In the browser, your JavaScript waits for clicks. On a server, Node.js waits for requests. Node's built-in node:http module can do this by itself, but this site uses Express, an npm package built on top of node:http that makes each route shorter to write.

express() creates app. app.listen(PORT) creates the Node.js HTTP server for us and starts it listening on that port. From then on, Node hands every request that arrives to app, and app passes it down the handlers in the order server.js added them, until one of them answers.

Each handler gets two objects. req is what the browser asked for: a method such as GET (req.method), a path such as /demo/echo (req.path), an optional query string after a ?, which Express turns into an object (req.query), and headers, which are small labeled notes about the browser (req.get() reads one). res is how you answer.

Every answer has three parts. The status code says how it went: 200 means OK, and 404 means not found. The Content-Type header says what kind of data is coming, such as HTML or JSON. The body is the data itself. res.status() sets the status code, and res.json() sets the Content-Type to JSON, turns an object into JSON text for the body, and sends the answer.

The code

This is the code that answers the demo below, copied from this site's own source. server.js creates app, serves the pages in PUBLIC_DIR, adds the demo with app.get, and ends with the 404 handlers and the error handler. Express tries the handlers from top to bottom.

server.js 
// Learn Node on Node: the server (APC 440, Module 11)
//
// This file creates the Express app, serves the pages in public/, adds each
// live demo, and ends with the 404 handlers and the error handler.
// The demo handlers live in demos.js.

import express from 'express';
import path from 'node:path';
import { echo, about } from './demos.js';

// Render tells your server which port to use through the PORT environment
// variable. On your own computer there is no PORT, so we fall back to 3000.
const PORT = process.env.PORT || 3000;

// The only folder the browser is allowed to read files from.
const PUBLIC_DIR = path.join(import.meta.dirname, 'public');

const app = express();

// Log every request in the terminal.
app.use((req, res, next) => {
  console.log(req.method, req.url);
  next();
});

// This site only answers GET. Every other method gets a 405.
app.use((req, res, next) => {
  if (req.method === 'GET') return next();
  res.set('Allow', 'GET');
  res.status(405).json({ error: 'Method not allowed. Use GET.' });
});

// Pages and files from public/. "/" is index.html, and a path with no
// extension is an .html page (/lessons/errors -> errors.html).
// express.static sets Content-Type and refuses paths that leave public/.
app.use(express.static(PUBLIC_DIR, { extensions: ['html'], redirect: false }));

// Live demos. Each handler is in demos.js.
app.get('/demo/echo', echo);
app.get('/demo/about', about);

// Unknown /demo/ paths get JSON. Any other unknown path gets the 404 page.
app.use('/demo', (req, res) => {
  res.status(404).json({ error: 'Not found' });
});
app.use((req, res) => {
  res.status(404).sendFile('404.html', { root: PUBLIC_DIR });
});

// The error handler has four parameters, so Express sends every error here.
// The details go to the terminal, never to the browser.
app.use((error, req, res, next) => {
  console.error(error);
  if (res.headersSent) return next(error);
  res.status(500).json({ error: 'Something went wrong on the server.' });
});

// app.listen creates the Node.js HTTP server for us and starts it.
app.listen(PORT, (error) => {
  if (error) throw error;
  console.log(`Server running at http://localhost:${PORT}`);
});

A request for /demo/echo gets logged, passes the GET check, finds no matching file in public/, and reaches app.get('/demo/echo', echo). Then echo in demos.js builds the answer.

demos.js 
// The only request headers echo repeats back. Others, like cookies, stay private.
const SAFE_HEADERS = ['user-agent', 'accept', 'accept-language'];

// GET /demo/echo: answers with what the browser sent in its request.
export function echo(req, res) {
  const headers = {};
  for (const name of SAFE_HEADERS) {
    if (req.get(name)) headers[name] = req.get(name);
  }
  res.status(200).json({
    method: req.method,
    path: req.path,
    query: req.query,
    headers,
  });
}

What just happened

      
Your browser sent a request, and the server sent back a description
      of that request as JSON.

      
    
        
  • HTTP 200 OK is the status code that
        echo passed to res.status().
    • 
        
  • "method": "GET": the button asked with GET, the
        method a browser uses to fetch something.
    • 
        
  • "path": "/demo/echo" is the same for both buttons.
        req.path is the part of the URL before the
        ?.
    • 
        
  • "query" is empty ({}) the first time. The
        second time it is { "name": "Ada", "lesson": "1" }, which
        Express built from the query string. The 1 arrives in
        quotes because everything in a URL is text. Your code has to turn it
        into a number if it needs one.
    • 
        
  • "headers" holds just three entries.
        user-agent names your browser, accept is
        */* (the button will take any kind of answer), and
        accept-language lists your browser's languages. Your
        browser sends other headers too, but echo uses
        req.get() to copy only the names in
        SAFE_HEADERS.
    • 
      

      
You did not see one part of the answer: the
      Content-Type: application/json; charset=utf-8 header that
      res.json() set. To see it, open your browser's developer
      tools, go to the Network tab, run the demo again, and click the
      echo request.
