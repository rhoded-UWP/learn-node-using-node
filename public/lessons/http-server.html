Lesson 1

The HTTP server

How a Node.js server receives a request and answers it with a status code, a Content-Type, and a body.

The idea

In the browser, your JavaScript waits for clicks. On a server, Node.js waits for requests. The built-in node:http module gives you http.createServer(). You hand it a function, and Node calls that function once for every request that arrives.

Your function gets two objects. request is what the browser asked for: a method such as GET, a path such as /demo/echo, an optional query string after a ?, and headers, which are small labeled notes about the browser. response is how you answer.

Every answer has three parts. The status code says how it went: 200 means OK, and 404 means not found. The Content-Type header says what kind of data is coming, such as HTML or JSON. The body is the data itself. response.writeHead() sends the first two, and response.end() sends the body and finishes the answer.

The code

This is the code that answers the demo below, copied from this site's own source. First, server.js creates the server and starts listening on a port.

server.js 
const server = http.createServer((request, response) => {
  // If anything inside handleRequest throws, answer with a 500 instead of
  // crashing. The details go to the terminal, never to the browser.
  handleRequest(request, response).catch((error) => {
    console.error(error);
    if (!response.headersSent) {
      sendJson(response, 500, { error: 'Something went wrong on the server.' });
    } else {
      response.end();
    }
  });
});

server.listen(PORT, () => {
  console.log(`Server running at http://localhost:${PORT}`);
});

Inside handleRequest, new URL() splits the request's URL into a path and query parameters. A path that starts with /demo/ is looked up in DEMOS. If no demo matches, the answer is a 404.

server.js 
// Each demo path and the function in demos.js that answers it.
const DEMOS = {
  '/demo/echo': echo,
};
  const url = new URL(request.url, 'http://localhost');

  if (url.pathname.startsWith('/demo/')) {
    const demo = DEMOS[url.pathname];
    if (!demo) return sendJson(response, 404, { error: 'Not found' });
    return demo(request, response, url);
  }

Finally, echo in demos.js builds the answer, and sendJson sets the status code and Content-Type and sends the body.

demos.js 
// Every JSON answer goes through here, so the status code and Content-Type
// are always set the same way.
export function sendJson(response, status, data) {
  response.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  response.end(JSON.stringify(data));
}

// The only request headers echo repeats back. Others, like cookies, stay private.
const SAFE_HEADERS = ['user-agent', 'accept', 'accept-language'];

// GET /demo/echo: answers with what the browser sent in its request.
export function echo(request, response, url) {
  const headers = {};
  for (const name of SAFE_HEADERS) {
    if (request.headers[name]) headers[name] = request.headers[name];
  }
  sendJson(response, 200, {
    method: request.method,
    path: url.pathname,
    query: Object.fromEntries(url.searchParams),
    headers,
  });
}

What just happened

      
Your browser sent a request, and the server sent back a description
      of that request as JSON.

      
    
        
  • HTTP 200 OK is the status code that
        echo passed to sendJson.
    • 
        
  • "method": "GET": the button asked with GET, the
        method a browser uses to fetch something.
    • 
        
  • "path": "/demo/echo" is the same for both buttons.
        The path is the part of the URL before the ?.
    • 
        
  • "query" is empty ({}) the first time. The
        second time it is { "name": "Ada", "lesson": "1" }. The
        1 arrives in quotes because everything in a URL is text.
        Your code has to turn it into a number if it needs one.
    • 
        
  • "headers" holds just three entries.
        user-agent names your browser, accept is
        */* (the button will take any kind of answer), and
        accept-language lists your browser's languages. Your
        browser sends other headers too, but echo copies only the
        names in SAFE_HEADERS. Node gives header names in
        lowercase, which is why the code looks up 'user-agent'.
    • 
      

      
You did not see one part of the answer: the
      Content-Type: application/json; charset=utf-8 header that
      sendJson set. To see it, open your browser's developer
      tools, go to the Network tab, run the demo again, and click the
      echo request.
