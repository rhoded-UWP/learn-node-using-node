Lesson 2

Modules and npm

How a Node.js project splits its code into modules, loads packages with import, and describes itself in package.json.

The idea

Each JavaScript file in a Node.js project is a module. Its variables stay private unless it shares them with export, and it loads what other modules share with import. In this site, demos.js exports the demo handlers, and server.js imports them.

The text after from says where the module comes from. This project uses three kinds:

  • 'node:path' and 'node:fs/promises': the node: prefix means a core module that is built into Node.js. There is nothing to install.
  • 'express': a plain name means a package that npm installed into the node_modules folder.
  • './demos.js': a name that starts with ./ means a file in this project, found next to the file that imports it. The .js is part of the name.

package.json describes the project to Node.js and npm. Its dependencies list the packages your code imports by name. npm installs those, the packages they need, and the packages those need. Express is this site's only dependency because everything else it does, such as reading files and joining folder paths, comes from Node's core modules.

The code

This is the code behind the demo below, copied from this site's own source. First, the whole package.json, from the project's top folder:

package.json 
{
  "name": "learn-node-on-node",
  "version": "1.0.0",
  "private": true,
  "description": "A Node.js tutorial site served by the Node.js code it teaches. APC 440, Module 11.",
  "type": "module",
  "main": "server.js",
  "scripts": {
    "start": "node server.js",
    "dev": "node --watch server.js"
  },
  "engines": {
    "node": ">=24"
  },
  "license": "UNLICENSED",
  "dependencies": {
    "express": "^5.3.0"
  }
}

Four of its fields matter for this lesson:

  • "type": "module" tells Node.js that this project's .js files are ES modules, the kind that use import and export.
  • "scripts" gives commands short names. npm start runs node server.js, which is how Render starts the site. npm run dev runs node --watch server.js, which restarts the server each time you save a file.
  • "engines" says which Node.js versions the project is written for: ">=24" means version 24 or newer.
  • "dependencies" lists the packages the code imports by name. "^5.3.0" means Express 5.3.0 or any newer 5.x version. package-lock.json records the exact version of every package that was installed, so npm ci installs the same set everywhere, including on Render.

server.js starts with three imports, one of each kind. express and path have no curly braces: each one takes the one main thing that module exports. { echo, about } has curly braces: it takes two exports by name, and the names must match the export function lines in demos.js.

server.js 
import express from 'express';
import path from 'node:path';
import { echo, about } from './demos.js';

Further down, server.js connects the demo's path to the about handler it imported.

server.js 
// Live demos. Each handler is in demos.js.
app.get('/demo/echo', echo);
app.get('/demo/about', about);

demos.js imports two functions from a core module and finds the project folder with import.meta.dirname. ES modules have no __dirname, so this is how a module finds the folder it is in.

demos.js 
import { readFile, readdir } from 'node:fs/promises';
import path from 'node:path';

// The project folder. demos.js sits next to package.json and node_modules.
const PROJECT_DIR = import.meta.dirname;

Finally, about reads package.json as text, turns it into an object with JSON.parse, and counts the folders in node_modules. await waits for each file system answer without stopping the server. Lesson 4 explains how that works.

demos.js 
// GET /demo/about: facts about this project, read from its own files.
export async function about(req, res) {
  const text = await readFile(path.join(PROJECT_DIR, 'package.json'), 'utf8');
  const pkg = JSON.parse(text);

  // Every package npm installed has its own folder in node_modules.
  // Names that start with a dot, like .package-lock.json, are npm's notes.
  const entries = await readdir(path.join(PROJECT_DIR, 'node_modules'), { withFileTypes: true });
  const packagesInstalled = entries.filter(
    (entry) => entry.isDirectory() && !entry.name.startsWith('.'),
  ).length;

  res.status(200).json({
    name: pkg.name,
    version: pkg.version,
    type: pkg.type,
    dependencyCount: Object.keys(pkg.dependencies).length,
    packagesInstalled,
  });
}

What just happened

      
The server read two things on its own disk, its
      package.json file and its node_modules folder,
      and described them as JSON.

      
    
        
  • HTTP 200 OK is the status code that
        about passed to res.status().
    • 
        
  • "name": "learn-node-on-node" and
        "version": "1.0.0" are copied from
        package.json. The server reads the file again every time
        you run the demo.
    • 
        
  • "type": "module" is the field that lets
        server.js and demos.js use
        import.
    • 
        
  • "dependencyCount": 1:
        Object.keys lists the names inside
        dependencies, and the only one is
        express.
    • 
        
  • "packagesInstalled": 65: one dependency, but 65
        package folders. Express lists 28 packages of its own, such as
        router, which matches paths to handlers, and
        send, which sends files. Some of those list more. npm
        installed every one, and package-lock.json lists all
        65.
    • 
      

      
That is why node_modules is never saved in Git (it is
      listed in .gitignore). Anyone with
      package.json and package-lock.json can rebuild
      it with npm ci, and Render does exactly that before it
      starts the site.
