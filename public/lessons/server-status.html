Lesson 6

Server status

A Node.js server is one program that keeps running, so it can remember things between requests and report on itself.

The idea

JavaScript in a browser starts over every time you load a page. This server is different. It starts once and then keeps running, answering request after request. A variable made when it starts stays in memory for as long as the server runs.

That lets the server keep a count. A small piece of middleware, a function that Express runs on a request before any route sees it, adds 1 to a counter and then calls next() to pass the request along.

Node.js can also report on itself through the global process object: which version of Node is running, on which operating system, how long it has been running, and how much memory it is using.

The count lives only in memory. There is no database yet, so it goes back to 0 every time the server restarts.

The code

This is the code behind the demo, copied from this site's own source. First, the counter, the middleware that counts requests, and the status handler:

demos.js 
// When the server started. This line runs once, when server.js imports demos.js.
const startedAt = new Date();

// How many requests the server has answered since it started. It lives in
// memory only, so it goes back to 0 every time the server restarts.
let requestsSinceStart = 0;

// Middleware: count requests. server.js runs it before express.static, so it
// counts every request: pages, styles, scripts, icons, and demos.
export function countRequests(req, res, next) {
  requestsSinceStart += 1;
  next();
}

// GET /demo/status: facts about this running server, right now.
export function status(req, res) {
  const memoryBytes = process.memoryUsage().rss;
  res.status(200).json({
    nodeVersion: process.version,
    platform: process.platform,
    uptimeSeconds: Math.round(process.uptime()),
    requestsSinceStart,
    memoryUsedMB: Math.round(memoryBytes / 1024 / 1024),
    startedAt: startedAt.toISOString(),
  });
}

process.uptime() is the number of seconds since Node started. process.memoryUsage().rss is the memory the whole Node program is using, in bytes. Dividing by 1024 twice turns it into megabytes.

In server.js, the order matters. Express runs app.use middleware in the order it is written, so countRequests comes first, before the 405 check and before express.static. That way it sees every request, even ones that never reach a route.

server.js 
// Count every request, before anything else can answer it.
app.use(countRequests);

Further down, one line connects the demo's path to the handler:

server.js 
app.get('/demo/status', status);

What just happened

      
The server answered with HTTP 200 and six facts about itself:

      
    
        
  • nodeVersion and platform: the
        version of Node.js running this site, such as "v26.10.0",
        and the operating system it runs on, such as "win32" for
        Windows or "linux" on Render.
    • 
        
  • uptimeSeconds and startedAt: how
        long the server has been running, and the moment it started.
        startedAt stays the same on every click, because that line
        ran only once.
    • 
        
  • memoryUsedMB: the memory Node is using right now,
        in megabytes. It can move up or down a little between clicks.
    • 
        
  • requestsSinceStart: every request the server has
        answered since it started, counting this one. The counter adds 1
        before the status handler runs, so the number you see
        includes the request that asked for it.
    • 
      

      
Clicking the button twice in a row makes
      requestsSinceStart go up by exactly 1. The button sends one
      request, so the server counts one.

      
After you reload the page, it goes up by more than 1. That is because
      one page load is several requests. The browser first asks for the page,
      /lessons/server-status. Then it reads the HTML and finds
      other files it needs, and asks the server for each one:
      /styles.css, /js/try-it.js, and usually
      /favicon.svg, the tab icon. Every one of those requests
      passes through countRequests before
      express.static sends the file. When this server was tested,
      loading a page and its three files and then asking for the status moved
      the count up by 5: 4 for the page load and 1 for the status request.
      The server's terminal shows the same thing, one line per request.

      
The lesson: the server only counts requests, and a browser makes many
      of them. A page that links more stylesheets, scripts, or images costs
      even more requests every time someone loads it.
